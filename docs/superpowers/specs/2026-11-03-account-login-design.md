# 账号编辑与交互式登录设计（待用户确认）

## 用户需求

账号建档不强制密码或登录名；已有账号可编辑；支持平台原生密码、短信验证码、扫码流程；登录后保存凭证并管理登录状态。所有构建与测试在 GitHub Actions 执行，不进行本地构建验证。

## 当前代码确认的问题

1. AccountSidebar.submit 要求 name 和 username 非空，阻碍扫码建档。
2. 数据库和 Tauri 命令均缺少账号编辑接口。
3. AccountWorkspace 显示截图，但没有点击、文本输入或按键命令，因此截图提示中的输入登录不可操作。
4. 会话打开标志被用于在线徽章，不能代表平台认证成功。
5. check_account_session 每次都导航平台首页；登录期间轮询可能破坏验证码或扫码过程。
6. 平台会话检查主要依靠 URL，可能把尚未跳转的未登录页面误判成已登录。
7. 已有 Cookie 加密保存/恢复；没有 localStorage/sessionStorage 持久化。
8. get_account_password/get_account_cookies 对 SQL 可空字段使用 optional 的类型需要复核：有记录但字段 NULL 与无记录应分别处理。

## 推荐实现

### 账号建档与编辑

只要求平台、备注名。用户名默认空字符串，兼容数据库 NOT NULL 列；密码可选。编辑备注、用户名、分组和代理。账号平台保持不可变，避免把原平台凭证用于另一个平台；跨平台通过新建账号处理。密码留空保留已有密码，提供明确清除选项。代理改变时关闭旧会话，并使展示状态回到未检测；保留同平台的已存凭证以便新实例恢复。后端统一校验名称、平台和代理，不只依赖前端。

### 平台原生登录交互

沿用现有每账号隔离的 Obscura BrowserContext。截图使用固定视口而非 full_page，前端按原图尺寸换算点击坐标；CDP Input 命令提供点击、按键、输入文本和滚动。平台原生页面决定其支持的登录方式，不以一套猜测选择器强制密码登录。手机号、验证码、密码直接输入当前聚焦的页面字段；验证码只用于当次交互，不写入账号资料。二维码由页面显示，可刷新截图；手机确认后用户执行登录检查与保存。

### 凭证与状态

区分会话是否打开与平台登录状态。登录期间不调用会主动导航的后台检测，不自动触发掉号短信。用户完成登录后执行检测；检测确认为登录才保存凭证。保存失败明确显示错误，不能显示已保存。

以带版本的加密凭证快照保存 Cookie 及按 origin 分组的 localStorage/sessionStorage；兼容旧 Cookie 数组格式。创建 context 后先在 about:blank 恢复 Cookie，再导航到平台；按 origin 恢复存储并刷新，使应用初始化读取凭证。只保存本账号已访问的受信平台 origin，不恢复到任意页面。无痕/浏览器重启可能使部分平台要求重新扫码，不保证永久免登录。

### 防止误判与错误处理

检查策略需要平台正向证据和登录页负向证据，URL 未包含 login 不能单独作为已登录的充分条件。找不到可靠证据时显示未确认，不自动保存为在线。网络错误与凭证失效分开处理，只有已登录到失效的状态转换才触发掉号通知，避免每次手动检查重复短信。

## 其他可选方案

- 可见 Chromium 窗口：交互直接、平台兼容面更大，但新增引擎依赖及跨平台打包与会话接管成本；当前作为 Obscura 无法完成登录时的后续方案。
- 只增加登录方式按钮：仍然没有页面输入能力，不满足本次目标。

## 验证计划

GitHub Actions 验证 TypeScript/Rust 编译和三平台打包，并加入账号编辑/可选登录名的数据库测试、旧新凭证格式兼容测试、截图坐标换算与参数校验测试。真实平台登录仍需要真实账号及手机验证码/扫码确认，不以构建成功声称登录已通过。

## 补充核查与验收矩阵

### 登录状态的误判风险

- 抖音和小红书目前仅检查 URL 不含 login；CSDN 也主要依赖登录地址的负向排除，不能据此确认认证成功。
- 公众号将任意 cgi-bin 路径视为登录成功，范围过宽，需要确切的认证页面/标记与当前登录证据组合。
- 自定义平台没有配置 logged_in_pattern 时也使用“不含 login”作为在线证据；应改为未确认，并提示用户配置正向证据。
- 后台监控会对非 Offline 账号发起导航；需要仅对已认证账号执行，交互登录和编辑期间跳过。
- 手动检测目前每次失败都可能发短信；改为仅 Online → Offline 转换触发，初次等待扫码不属于掉号。

### 验收用例

| 场景 | 必须满足的结果 |
|---|---|
| 只填平台、备注新增账号 | 成功建档，不要求用户名和密码 |
| 修改备注和分组 | 列表与工作台同步，账号 ID 和任务关联不变 |
| 密码留空保存编辑 | 原密码保留；清除密码需独立明确操作 |
| 修改代理 | 旧会话关闭，下一次连接使用新代理，状态不误报在线 |
| 点击缩放截图 | 根据实际截图尺寸换算视口坐标，不按 CSS 像素直接发送 |
| 验证码输入 | 文本发往当前隔离页，验证码不持久化、不进入日志或 MCP 返回 |
| 二维码登录等待 | 刷新画面不反复导航，不触发掉号短信 |
| 空 Cookie/只有匿名 Cookie | 不显示为已登录，不自动标记凭证保存成功 |
| 登录检测通过、凭证保存失败 | 明确显示保存失败，不能显示已保存 |
| 重启恢复旧 Cookie 数组 | 仍可读取旧格式并在后续保存时迁移 |
| 新格式存储恢复 | Cookie 在首次导航前恢复；Web Storage 仅恢复到匹配 origin |
| 检测网络异常 | 显示检测失败/未知，不当作确认掉号 |
| 多次检测同一失效账号 | 仅第一次已登录到失效转换发通知 |
| 切换账号标签 | 页面、计时器、输入缓存和显示状态不得沿用上一账号 |
